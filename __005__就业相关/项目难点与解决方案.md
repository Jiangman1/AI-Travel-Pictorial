# 智能自动营销项目 — 难点与解决方案

> 本文档从项目实际代码与架构中提炼开发过程中遇到的主要困难及对应解法，可用于技术复盘、面试准备或课程讲解。

---

## 一、大模型文案生成

### 难点 1：LLM 输出格式不稳定，下游节点难以解析

**现象**  
文案生成节点需要向配图、发布、预览等下游节点传递 `title`、`content`、`site` 三个固定字段。若模型返回自由文本或字段缺失，后续节点无法正常运行。

**解决方案**
- 使用 **Pydantic 模型**（`ToutiaoTravelOutput`）定义输出 schema，字段含长度与语义约束。
- 结合 **JsonOutputParser**，将 `format_instructions` 注入 System Prompt，强制模型按 JSON 结构返回。
- 采用 **流式输出 + 拼接后统一解析**：`my_llm.stream()` 逐块收集完整响应，再 `parser.parse()` 一次性解析，兼顾体验与稳定性。

**相关代码**：`__001__workflow/nodes/__001__text_generate_node.py`

---

### 难点 2：生成内容不符合头条平台规范

**现象**  
标题过长、正文超字数、语气不符合信息流阅读习惯，会导致发布失败或推荐效果差。

**解决方案**
- 在 Prompt 中明确平台约束：标题 ≤30 字、正文 ≤800 字、旅行攻略风格。
- Pydantic Field 的 `description` 再次强调字数与风格要求，形成「Prompt + Schema」双重约束。
- 发布前增加 **校验节点**（`check_text_image_node`），标题或正文为空时直接中断流程，避免无效发布。

**相关代码**：`__001__workflow/nodes/__001__text_generate_node.py`、`__001__workflow/nodes/__003__check_text_image_node.py`

## 二、LangGraph 工作流编排

### 难点 3：多步骤流程存在条件分支，简单函数链难以维护

**现象**  
完整链路包含：文案生成 →（AI 生图 **或** 百度爬虫）→ 校验 →（通过 **才** 发布）→ HTML 预览。存在两处条件分支，用线性脚本难以清晰表达状态流转。

**解决方案**
- 使用 **LangGraph StateGraph** 编排 6 个节点，以 `WorkflowAgentState` 作为统一状态载体。
- 通过 **conditional_edges** 实现两处路由：
  - `image_source == "baidu"` → 百度配图节点，否则 → AI 生图节点；
  - `is_can_publish_toutiao == True` → 发布节点，否则 → 直接 END。
- 各节点只负责读写 state 中自己关心的字段，解耦清晰，后续加「人工审核」「重试」等节点成本低。

**相关代码**：`__001__workflow/workflow.py`

---

### 难点 4：同步与异步调用混用导致报错

**现象**  
Playwright 发布、LangGraph 执行均为异步；若在 FastAPI 或 MCP Client 中用同步方式调用，会出现事件循环冲突或阻塞。

**解决方案**
- 工作流入口统一为 `async def run_workflow()`，内部使用 `graph.ainvoke()`。
- FastAPI 接口声明为 `async`，直接 `await run_workflow()`。
- MCP Client 中 Agent 调用使用 **`ainvoke`**，注释明确「MCP 工具为异步实现，需使用 ainvoke 避免 sync 调用报错」。

**相关代码**：`__001__workflow/workflow.py`、`__002__fastapi/__001__server.py`、`__004__mcp/__002__mcp_client.py`

## 三、配图模块（AI 生图 + 百度爬虫）

### 难点 5：AI 生图质量不可控（文字乱入、AI 感强、低画质）

**现象**  
旅行配图若出现乱码文字、畸形人物或明显 AI 痕迹，不适合作为头条封面。

**解决方案**
- 设计专用 **正向 Prompt 模板**：强调旅行场景、地点、明亮色调，并明确「图片中不能有任何文字」。
- 配置 **负向 Prompt**（`DEFAULT_NEGATIVE_PROMPT`）：排除低分辨率、肢体畸形、蜡像感、画面过饱和等。
- 启用百炼 `prompt_extend=True` 自动扩展提示词，提升画面丰富度。

**相关代码**：`__001__workflow/nodes/__002__image_generate_node.py`

---

### 难点 6：百炼 API 返回结构嵌套深，图片 URL 不易提取

**现象**  
DashScope 多模态接口返回的 JSON 层级较深，图片 URL 藏在 `output.choices[0].message.content[]` 中，直接取值易报错。

**解决方案**
- 封装 `_extract_image_url()`，逐层安全访问并用 `try/except` 捕获 `AttributeError`、`KeyError` 等。
- 遍历 `content` 数组，查找含 `image` 字段的 dict 项。
- 生图成功后单独调用 `_download_image()` 将远程 URL 落盘到 `picture/` 目录，供 Playwright 上传使用。

**相关代码**：`__001__workflow/nodes/__002__image_generate_node.py`

---

### 难点 7：AI 生图慢且贵，单一配图方案难以满足所有场景

**现象**  
AI 生图耗时长（数秒～数十秒）、有 API 成本；运营有时更需要真实风景图且希望一次多张配图。

**解决方案**
- 设计 **双通道配图架构**：`image_source=ai` 走百炼生图（1 张）；`image_source=baidu` 走百度爬虫（最多 4 张）。
- 通过 API 参数、环境变量 `IMAGE_SOURCE` 或前端 Radio 一键切换，无需改工作流代码。
- LangGraph 条件边在文案节点后自动路由到对应配图节点。

**相关代码**：`__001__workflow/workflow.py`、`__001__workflow/nodes/__006__baidu_image_download_node.py`

---

### 难点 8：百度 acjson 接口返回不规范、反爬、图片链接失效

**现象**
- 接口偶尔返回非标准 JSON（含转义问题），`json.loads` 直接失败；
- 缺少 Referer / User-Agent 易被拒绝；
- 单条结果中图片 URL 字段名不统一（`middleURL`、`thumbURL`、`objURL` 等）；
- 部分 URL 下载失败或返回非图片内容。

**解决方案**
- 请求头模拟浏览器：设置 `User-Agent`、`Referer: https://image.baidu.com/`。
- JSON 解析失败时，用 **正则兜底**提取 `"data": [...]` 数组再二次解析。
- 按优先级遍历 `IMAGE_URL_KEYS` 提取可用 http://` 链接。
- **分页搜索**（`pn` / `rn`）+ URL 去重，凑够目标数量；单张下载失败不影响其他张（逐张 try，返回成功列表）。
- 搜索词规则：`地点 +「旅行」`，地点为空时 fallback 到标题。

**相关代码**：`common/baidu_image_utils.py`

## 四、Playwright 头条自动发布（RPA）

### 难点 9：首次使用需人工扫码登录，无法全自动

**现象**  
今日头条号后台需要登录态，Playwright 无法自动完成扫码验证。

**解决方案**
- 使用 Playwright **`storage_state`** 持久化 Cookie 到 `cookie/toutiao_state.json`。
- 实现 `is_on_login_page()`：检测 `article.web-login-union` 及「验证码登录」表单，判断是否在登录页。
- `check_is_in_login_page_and_login()` 循环等待（最多约 100 轮 × 10 秒），给用户留出扫码时间；登录完成后自动继续流程。
- 登录成功后调用 `save_login_state()` 保存状态，后续运行免登录。

**相关代码**：`__001__workflow/nodes/__004__auto_publish_toutiao_node.py`

---

### 难点 10：页面弹窗 / 遮罩层阻挡自动化操作

**现象**  
进入发文页后，平台常弹出引导或活动遮罩，导致后续元素无法点击。

**解决方案**
- 实现 `dismiss_popup_by_random_click()`：等待页面稳定后，在空白区域（如坐标 10,10）模拟点击，关闭遮罩弹框。
- 关键操作前增加固定等待（`wait_seconds`），给页面渲染和动画留出时间。

**相关代码**：`__001__workflow/nodes/__004__auto_publish_toutiao_node.py`

---

### 难点 11：富文本编辑器（ProseMirror）无法直接 fill 赋值

**现象**  
头条正文编辑器基于 ProseMirror，`input.fill()` 或 `set_value()` 往往无效，内容无法写入。

**解决方案**
- 对标题 textarea 和正文 ProseMirror 均使用 **`type(text, delay=30~50)`** 模拟逐字输入。
- 操作前先 `click()` 聚焦编辑器，再用 `wait_for(state="visible")` 确保元素就绪。

**相关代码**：`__001__workflow/nodes/__004__auto_publish_toutiao_node.py` — `fill_title()`、`fill_content()`

---

### 难点 12：图片上传控件为隐藏 file input，无法常规点击

**现象**  
「本地上传」的真实 `<input type="file">` 被 CSS 隐藏，直接 click 无效；多图上传还需等待异步上传完成。

**解决方案**
- 定位 `[data-e2e='image-upload']` 下的 file input，使用 **`set_input_files(paths)`** 一次性传入多张本地绝对路径。
- 上传前将相对路径统一转为绝对路径，并过滤不存在的文件。
- 等待预览区 `.image-list li` 出现最后一张，确认上传完成后再点 `[data-e2e='imageUploadConfirm-btn']` 确认插入。
- 上传超时设为 60 秒，适应大图或弱网环境。

**相关代码**：`__001__workflow/nodes/__004__auto_publish_toutiao_node.py` — `upload_images()`

---

### 难点 13：平台 DOM 结构可能改版，自动化脚本易失效

**现象**  
头条后台 class 名、按钮文案会随版本更新变化，硬编码选择器可能突然失效。

**解决方案**
- 优先使用 **`data-e2e`** 等相对稳定的数据属性定位关键按钮（如 `imageUploadConfirm-btn`）。
- 关键步骤均加 **`wait_for(state="visible/attached")`** 显式等待，避免竞态。
- 代码注释标明「若平台改版可再替换」及对应后台入口 URL，便于维护时快速定位。
- 整体流程包在 `try/except` 中，失败时打印异常并安全关闭浏览器，返回 `False` 而非崩溃。

**相关代码**：`__001__workflow/nodes/__004__auto_publish_toutiao_node.py`

## 五、路径与文件管理

### 难点 14：相对路径 / 绝对路径混用，跨模块引用失败

**现象**  
工作流、Playwright、FastAPI 静态服务、HTML 预览各自处理路径，Windows 与相对路径混用时易出现「图片不存在」。

**解决方案**
- 统一封装 **`get_file_path(relative_path)`**，以项目根目录为基准拼接绝对路径。
- Playwright 上传、HTML 预览、校验节点均通过该工具解析路径；绝对路径则直接使用。
- 图片文件名采用 **时间戳 + 标题前 5 字**，避免重名覆盖。

**相关代码**：`common/path_utils.py`、`__001__workflow/nodes/__004__auto_publish_toutiao_node.py`、`__001__workflow/nodes/__005__generate_html_node.py`

## 六、前端预览与 API 接入

### 难点 15：iframe 预览无法直接访问本地图片路径

**现象**  
Streamlit `components.html` 或 React iframe 渲染预览时，HTML 内 `<img src="picture/xxx.png">` 无法加载本地文件。

**解决方案**
- 在 `generate_html_node` 中将本地图片 **Base64 编码为 data URL**（`data:image/png;base64,...`）内嵌到 HTML。
- 生成完整独立 HTML 文档（含样式），前端无需额外挂载 `/picture` 静态路由即可预览。
- FastAPI 仍挂载 `/picture` 静态目录，供 React 页面其他场景使用。

**相关代码**：`__001__workflow/nodes/__005__generate_html_node.py`、`__002__fastapi/__001__server.py`

---

### 难点 16：全流程耗时长，HTTP 请求易超时

**现象**  
单次完整流程包含 LLM 生成、生图/爬虫、Playwright 发布，总耗时可达数分钟，默认 HTTP 超时会导致前端报失败。

**解决方案**
- Streamlit 与 React 客户端将请求 **timeout 设为 600 秒（10 分钟）**。
- FastAPI 使用异步 endpoint，避免阻塞其他请求。
- 前端展示 loading / spinner，明确提示「可能需要数分钟」。

**相关代码**：`__003__streamlit/__001__streamlit_web.py`、`__002__fastapi/static/src/App.jsx`

## 七、MCP Agent 集成

### 难点 17：ReAct Agent 工具调用顺序与意图不明确

**现象**  
用户说「生成并发布」时，Agent 可能只生成文案就停下来询问确认；或跳过配图直接发布。

**解决方案**
- 编写详细 **SYSTEM_PROMPT**，明确三步流程：文案 → 配图 → 发布。
- 规定：用户含「发布」「上线」等关键词时 **直接执行到底，不再询问确认**；仅生成文案/配图时才展示结果并询问是否继续。
- 将业务能力拆为 3 个独立 MCP Tool，便于 Agent 按步骤组合调用。

**相关代码**：`__004__mcp/__002__mcp_client.py`、`__004__mcp/__001__mcp_server.py`

---

### 难点 18：MCP 异步 Tool 与 LangChain Agent 调用方式不匹配

**现象**  
`publish_toutiao_article` 为 `async def`，若 Agent 用同步 `invoke` 调用会报错或阻塞。

**解决方案**
- MCP Server 中发布工具声明为 **async**。
- Client 端 Agent 统一使用 **`await agent.ainvoke()`** 执行对话与工具链。

**相关代码**：`__004__mcp/__001__mcp_server.py`、`__004__mcp/__002__mcp_client.py`

## 九、仍可优化的方向

| 方向 | 说明 |
|------|------|
| 发布失败重试 | 当前 Playwright 失败直接返回 False，可增加节点级重试或人工介入 |
| 配图降级策略 | 百度爬虫失败时自动 fallback 到 AI 生图 |
| 选择器维护 | 头条改版时需人工更新 DOM 选择器，可考虑配置化 |
| LLM 解析容错 | JSON 解析失败时可增加一次「修复 JSON」的 LLM 重试 |
| 并发与队列 | 批量主题发布时可引入任务队列，避免多个 Playwright 实例冲突 |
