# 智能自动营销项目 — 项目总结（就业向）

## 一、项目概述

**项目名称**：wuhan3_auto_marketing_project（智能自动营销助手）

**一句话介绍**：基于大语言模型 + LangGraph 工作流，实现「输入旅行主题 → 自动生成头条图文文案 → 配图（AI 生图 / 百度爬虫）→ 自动发布今日头条 → 前端预览」的全链路自动化营销系统。

**业务场景**：面向内容运营、新媒体营销场景，帮助运营人员快速批量产出旅行类头条图文并完成发布，降低人工撰写、找图、排版、上传的时间成本。

**典型输入示例**：`湖北荆州`、`新疆天山`、`都江堰`、`青岛三天两夜`

---

## 二、技术栈

| 类别 | 技术 | 用途 |
|------|------|------|
| 大模型 | LangChain + OpenAI 兼容 API | 文案生成（结构化 JSON 输出） |
| 工作流编排 | LangGraph | 多节点 DAG 流程编排与条件分支 |
| 多模态生图 | 阿里云百炼 DashScope（qwen-image-2.1-pro） | AI 旅行配图生成 |
| 图片爬虫 | requests + 百度 acjson 接口 | 按关键词批量下载配图（最多 4 张） |
| 浏览器自动化 | Playwright | 今日头条号后台自动发文、上传图片 |
| Web 后端 | FastAPI + Uvicorn | REST API 服务 |
| Web 前端 | React（CDN 引入）+ Streamlit | 双端交互界面 |
| 协议扩展 | MCP（Model Context Protocol） | 将核心能力封装为 Agent 可调用的 Tool |
| Agent | LangChain ReAct Agent + MCP Adapters | 自然语言驱动的全流程对话式操作 |
| 其他 | python-dotenv、Pydantic、BeautifulSoup4 | 配置管理、数据校验等 |

## 三、系统架构

### 3.1 整体分层

```
用户层
  ├── React Web 前端（FastAPI 静态页）
  ├── Streamlit 管理页
  └── MCP ReAct 对话客户端（命令行）

服务层
  ├── FastAPI Server（:8000）
  └── MCP Server（:8010）

业务层（LangGraph 工作流）
  ├── 文案生成节点
  ├── 配图节点（AI 生图 | 百度爬虫，条件分支）
  ├── 内容校验节点
  ├── 头条自动发布节点
  └── HTML 预览生成节点

基础设施层
  ├── common/llm.py          — LLM 封装
  ├── common/config.py       — 环境变量配置
  ├── common/baidu_image_utils.py — 百度图片工具
  └── common/path_utils.py   — 路径工具
```

### 3.2 LangGraph 工作流（核心）

```
START
  ↓
文案生成（LLM 生成 title / content / site）
  ↓
条件分支：image_source == "baidu" ?
  ├── 是 → 百度图片下载（最多 4 张）
  └── 否 → 百炼 AI 生图（1 张）
  ↓
校验（标题、正文、图片路径是否有效）
  ↓
条件分支：校验通过 ?
  ├── 是 → Playwright 自动发布头条
  └── 否 → END
  ↓
生成 HTML 预览（base64 内嵌图片）
  ↓
END
```

**状态对象 `WorkflowAgentState`** 贯穿全流程，字段包括：`user_input`、`toutiao_title`、`toutiao_content`、`toutiao_site`、`image_source`、`toutiao_image_path_list`、`toutiao_html`、`is_can_publish_toutiao`、`is_publish_success`、`output`。

## 五、核心功能模块

### 5.1 文案生成（text_generate_node）

- 使用 LangChain + Pydantic 结构化输出，生成头条旅行图文三要素：**标题**（≤30 字）、**正文**（≤800 字）、**地点关键词**。
- 采用流式输出（`my_llm.stream`），提升交互体验。

### 5.2 配图生成（双通道）

| 模式 | 实现 | 数量 | 说明 |
|------|------|------|------|
| AI 生图 | 百炼 qwen-image-2.1-pro | 1 张 | 根据标题+地点构造提示词，2048×2048 |
| 百度爬虫 | acjson 接口搜索下载 | 最多 4 张 | 关键词 = 地点 +「旅行」 |

通过 `image_source` 参数（`ai` / `baidu`）或环境变量 `IMAGE_SOURCE` 切换。

### 5.3 头条自动发布（auto_publish_toutiao_node）

- 基于 **Playwright** 操控 Chromium 浏览器。
- 自动填写标题、正文，上传本地配图，点击「预览并发布 → 确认发布」。
- 支持 **Cookie 持久化**（`cookie/toutiao_state.json`），首次需扫码登录，后续免登录。
- 含登录页检测、弹窗关闭、元素等待等健壮性处理。

### 5.4 HTML 预览（generate_html_node）

- 将标题、正文、配图（base64 data URL 内嵌）组装为完整 HTML 文档。
- 可直接在 React / Streamlit 的 iframe 中渲染，无需额外静态资源服务。

### 5.5 三种接入方式

1. **FastAPI + React**：`POST /receive_raw_json/`，浏览器访问 `http://127.0.0.1:8000`
2. **Streamlit**：调用 FastAPI 后端，展示发布结果与图文预览
3. **MCP + ReAct Agent**：自然语言对话驱动，如「帮我生成湖北荆州的头条图文并发布」

## 七、项目亮点（简历 / 面试可用）

1. **LangGraph 工作流编排**：用 StateGraph 实现多节点 DAG，支持条件分支（配图来源切换、发布前校验），状态在节点间流转，结构清晰、易扩展。

2. **LLM 结构化输出**：Pydantic + JsonOutputParser 约束模型输出格式，保证下游节点拿到稳定的 title / content / site 字段。

3. **多模态能力整合**：同一工作流内打通「文本生成 + 图像生成 / 爬虫下载」，体现 Agent 多工具协作思路。

4. **RPA 自动化发布**：Playwright 实现真实浏览器操作，含登录态持久化、元素定位、异常处理，贴近实际运营自动化需求。

5. **MCP 协议实践**：将业务能力封装为 MCP Tool，配合 ReAct Agent 实现自然语言驱动的全流程，符合当前 AI Agent 工程化趋势。

6. **前后端分离 + 双 UI**：FastAPI 提供 API，React / Streamlit 双端消费；HTML 预览采用 base64 内嵌，部署简单。

7. **可迁移 Skill**：百度图片爬虫封装为独立 Cursor Skill，整目录可复制到其他项目使用。

## 九、面试常见问题参考

**Q：为什么选择 LangGraph 而不是简单函数链？**  
A：节点多、有分支（配图来源、校验是否发布），LangGraph 的状态管理和条件边更清晰，后续加节点（审核、重试）成本低。

**Q：头条发布如何保证稳定性？**  
A：Playwright 显式等待元素、Cookie 持久化减少登录次数、路径校验与异常捕获；平台改版时需更新选择器。

**Q：AI 生图和百度爬虫如何取舍？**  
A：AI 生图风格统一、无版权顾虑但慢且贵；百度爬虫快、真实场景感强但需注意版权与图片质量，通过 `image_source` 按场景切换。

**Q：MCP 在本项目中的作用？**  
A：把文案、生图、发布拆成独立 Tool，Agent 可按用户意图动态组合调用，便于对接 Cursor、Claude Desktop 等 MCP 客户端。
