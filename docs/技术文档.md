# AutoMarketing 技术文档

> 旅行图文自动营销 MVP：输入一个地点，自动完成「文案生成 → 配图 → 校验 → HTML 预览 → 人工审核 → 头条发布」。
> 本文档描述当前代码的实际行为，与早期设计稿不一致的地方以代码为准。

## 1. 项目概览

| 项 | 说明 |
|---|---|
| 定位 | 个人实战项目，本地运行，未做公网部署 |
| 核心 | 用 LangGraph 把内容运营的重复流程编排成状态机 |
| 输入 | 一个地点关键词，例如「湖北荆州」 |
| 输出 | 一条可发布的图文（标题 + 正文 + 配图），以及一份独立 HTML 预览 |
| 编排 | 7 个节点、4 处条件路由、1 个人工中断点（可选） |
| 持久化 | LangGraph checkpoint 落 SQLite，按 `thread_id` 隔离 |

## 2. 技术栈

| 层 | 技术 |
|---|---|
| 编排 | LangGraph 1.x（`StateGraph` / `interrupt` / `Command(resume)`） |
| 模型 | LangChain + `langchain-openai`，OpenAI 兼容协议（当前接 DeepSeek） |
| 结构化输出 | Pydantic + `JsonOutputParser` |
| 生图 | 阿里云百炼 DashScope `MultiModalConversation`（模型可配置） |
| 爬虫 | `requests` + 百度图片 acjson 接口 |
| 自动发布 | Playwright（Chromium，`storage_state` 复用登录态） |
| 服务 | FastAPI + Uvicorn |
| 前端 | React 18 UMD + Babel Standalone（无构建步骤） |
| 管理页 | Streamlit |
| 工具协议 | MCP（`FastMCP` + `langchain-mcp-adapters`） |

## 3. 分层架构

```

│ 入口层                                                    │

┌───────────────▼──────────────────▼───────────────▼───────┐
│ 服务层                                                    │

│  MCP Server  generate_travel_image / publish_toutiao_...  │
└───────────────────────────┬───────────────────────────────┘
                            │
┌───────────────────────────▼───────────────────────────────┐
│ 业务层：LangGraph StateGraph                              │
│  文案 → 配图(ai|baidu) → 校验 → HTML → 审核(可选) → 发布 │
└───────────────────────────┬───────────────────────────────┘
                            │
```

关键点：**MCP 链路不经过 LangGraph**，它直接调用业务函数，是给对话式调用方准备的独立入口。

## 5. 状态定义

`WorkflowAgentState` 是贯穿全流程的字典：

| 字段 | 类型 | 由谁写入 | 说明 |
|---|---|---|---|
| `user_input` | str | 入口 | 用户输入的地点 |
| `image_source` | str | 入口 | `ai` / `baidu` |
| `require_human_approval` | bool? | 入口 | 是否在发布前中断 |
| `toutiao_title` | str | 文案节点 | 标题 |
| `toutiao_content` | str | 文案节点 | 正文 |
| `toutiao_site` | str | 文案节点 | 地点 |
| `toutiao_image_path_list` | list[str] | 配图节点 | 本地图片绝对路径 |
| `is_can_publish_toutiao` | bool | 校验节点 | 是否通过校验 |
| `toutiao_html` | str | HTML 节点 | 内嵌 base64 图片的完整 HTML |
| `is_human_approved` | bool? | 审核节点 | 审核结论 |
| `is_publish_success` | bool | 发布/校验/审核 | 最终结果 |
| `output` | str | 各节点 | 给前端展示的提示语 |

注意：节点目前**返回整个 state**，靠 LangGraph 的字典合并语义更新字段。

## 6. 工作流

### 6.1 节点与边

```
START
  │
  ▼
text_generate_node ──(image_source)──┬─ "ai"    → image_generate_node
  │                                  └─ "baidu" → baidu_image_download_node
  ▼
check_text_image_node ──(is_can_publish_toutiao)──┬─ true  → generate_html_node
  │                                               └─ false → END
  ▼
generate_html_node ──(require_human_approval)──┬─ true  → human_approval_node
  │                                            └─ false → auto_publish_toutiao_node
  ▼
human_approval_node ──(is_human_approved)──┬─ true  → auto_publish_toutiao_node
  │                                        └─ false → END
  ▼
auto_publish_toutiao_node → END
```

### 6.2 四个路由函数

| 函数 | 判断依据 | 分支 |
|---|---|---|
| `route_image_node` | `image_source == "baidu"` | 下载 / 生图 |
| `route_after_check` | `is_can_publish_toutiao` | HTML / END |
| `route_after_html` | `require_human_approval` | 审核 / 直接发布 |
| `route_after_human_approval` | `is_human_approved` | 发布 / END |

新增一种图源只需加一个节点 + 改 `route_image_node`，主干不用动。

### 6.3 节点职责

| 节点 | 职责 | 失败处理 |
|---|---|---|
| `text_generate_node` | 流式调用模型，拼完整后 `JsonOutputParser` 解析 | 异常向上抛 |
| `image_generate_node` | 拼提示词 → 百炼生图 → 下载到 `picture/` | 返回空列表并写明原因 |
| `baidu_image_download_node` | 抓取候选图，最多保存 4 张 | 返回空列表 |
| `check_text_image_node` | 校验标题/正文/图片路径存在 | `is_can_publish_toutiao=False` |
| `generate_html_node` | 图片转 base64 内嵌，生成预览 HTML | — |
| `human_approval_node` | `interrupt()` 暂停，等待审批 | 拒绝则结束 |
| `auto_publish_toutiao_node` | Playwright 驱动头条后台发文 | 捕获异常并回传原因 |

## 7. 人工审核（HITL）

```
前端 POST /receive_raw_json/ (require_human_approval=true)
  → graph.invoke(...) 在 human_approval_node 调用 interrupt()
  → 状态写入 SQLite，返回 {needs_approval: true, thread_id, toutiao_html}
前端展示预览
  → POST /approve_workflow/ {thread_id, approval:"批准"}
  → graph.invoke(Command(resume="批准"), config)
  → 节点从头重放，interrupt() 直接返回 resume 值
  → 继续发布或结束
```

使用约束：**`interrupt()` 之前的代码会被重放**，所以中断点之前不能有副作用（写文件、发请求、扣费调用）。

## 8. 关键实现细节

### 8.1 模型与配置

- `common/llm.py` 用 `ChatOpenAI`，只依赖 `MODEL_API_KEY` / `MODEL_BASE_URL` / `MODEL_NAME`，换供应商只改 `.env`。
- `.env` 查找顺序：`ENV_FILE` → 项目根 `.env` → 旧机器绝对路径。缺 `MODEL_*` 时会打印中文警告。

### 8.2 双通道配图

| 通道 | 实现 | 产物 |
|---|---|---|
| `ai` | 百炼 `MultiModalConversation`，模型由 `BAILIAN_IMAGE_MODEL` 指定，默认 2048×2048 | 1 张 |
| `baidu` | acjson 接口搜索，多 URL 字段回退、魔数校验 | 最多 4 张 |

生图失败时会打印 `status_code / code / message`，并把原因写进 `output`，不再假装成功。

### 8.3 预览 HTML

- 图片读成 base64 内嵌，前端 `iframe srcDoc` 直接渲染，无需额外静态服务。
- 正文做 `html.escape`，避免破坏结构。
- 同时落盘到 `output/toutiao_preview.html`，方便离线查看。

### 8.4 自动发布

- `headless=False`，首次需要扫码登录，登录态写入 `cookie/toutiao_state.json`。
- 正文是 ProseMirror 富文本，只能 `type` 逐字输入，不能 `fill`。
- 图片上传控件是隐藏的 `input[type=file]`，用 `set_input_files`。
- 发布分两段：先点「预览并发布」，再点「确认发布」。

### 8.5 并发模型

- FastAPI 是异步的，LangGraph 图是同步的，用 `asyncio.to_thread` 包一层，避免阻塞事件循环。
- `SqliteSaver` 是同步实现，单机单进程可用，未做并发压测。

## 11. 设计取舍

**为什么用状态机而不是一条脚本**
节点可替换、可单测，分支条件集中在 4 个路由函数里；新增图源或新增审核规则不用改主干。

**为什么 checkpoint 落 SQLite**
HITL 需要跨请求、跨进程恢复；SQLite 零部署，`thread_id` 天然隔离。

**为什么前端不进构建链**
Demo 优先，React UMD + Babel Standalone 直接在浏览器编译 `App.jsx`，改完刷新即生效。

**为什么 MCP 不复用图**
MCP 面向对话式调用，工具粒度是「生成一张图」「发一篇文章」，硬套整图反而让 Agent 难用。

## 12. 已知限制

| 项 | 现状 |
|---|---|
| 鉴权 | 接口无鉴权，只能本机/内网使用 |
| 发布结果 | 点击确认后即返回成功，未回读平台提示 |
| 并发 | 同步 SqliteSaver，单进程；未压测 |
| 状态更新 | 节点返回整个 state，字段多了容易误覆盖 |
| 平台适配 | 头条改版需要维护选择器 |
| 素材 | 百度通道只用于技术验证，抓取图片不用于公开演示 |
| 首次发布 | 需人工扫码登录 |

## 13. 排错速查

| 现象 | 排查方向 |
|---|---|
| 前端「配图生成失败」 | 看服务端 `百炼生图失败: model=..., status_code=...`；401 换 Key，403 换模型，400 改尺寸 |
| 前端「图片文件不存在」 | `picture/` 为空，说明下载失败，看上一条 |
| 前端「未生成 HTML 预览」 | 工作流在校验节点就结束了，先解决图片问题 |
| 发布失败 | 多为未安装 Chromium 或未登录；先 `playwright install chromium` |
| 启动报 `No module named ...` | 依赖没装全，重跑 `pip install -r requirements.txt` |
| 端口被占用 | 关掉旧进程，或改 `__001__server.py` 里的端口 |
