## 一、项目状态与演示方式

**当前状态**：本地可运行的 MVP，已完成端到端闭环，尚未做公网部署。

**不直接发在线服务链接的原因**：

1. 发布环节依赖真实的头条号登录态（`cookie/toutiao_state.json`），公开访问等于把账号操作权限交给外部；
2. 服务接口目前没有鉴权，任何拿到链接的人都能触发发布；
3. 模型与生图依赖个人 API Key，不适合长期暴露在公网。

## 二、功能范围

### 已实现

- LangGraph 7 节点工作流：文案生成 → 配图（双通道）→ 内容校验 → HTML 预览 → 人工审核（可选）→ 头条发布
- 4 处条件路由：配图来源、是否可发布、是否人工审核、审批结论
- LLM 结构化输出：Pydantic + JsonOutputParser，稳定产出 title / content / site
- 双通道配图：百炼 `qwen-image-2.1-pro` 生图（1 张）；百度图片下载（最多 4 张，多候选回退）
- 人工审核：`interrupt` + `Command(resume)` + SQLite checkpoint，支持跨进程恢复
- Playwright 自动发布：登录态持久化、登录页轮询、富文本输入、多图上传、两段确认
- 三种接入：FastAPI + React、Streamlit、MCP Tool + ReAct Agent
- 预览 HTML：图片 base64 内嵌，可离线打开

### 已知限制（主动说明）

- 发布接口无鉴权，仅限本机/内网使用
- 发布成功为乐观返回，未回读平台成功提示
- SQLite 为单机 checkpoint，未做并发压测
- MCP 链路直接调用业务函数，不经过工作流
- 头条页面改版时需更新选择器

## 六、线上沟通建议（15–20 分钟）

1. **2 分钟**：项目定位与业务闭环（输入主题 → 文案 → 配图 → 校验 → 预览 → 审核 → 发布）
2. **5 分钟**：现场跑一条流程，重点讲 LangGraph 条件边与 `interrupt` 恢复
3. **5 分钟**：讲 2–3 个真实难点（节点重放、同步/异步混用、Playwright 富文本）
4. **3 分钟**：主动说边界与改进方向（鉴权、发布校验、并发、MCP 一致性）
5. **3 分钟**：回答提问

**演示前检查**：模型 Key 可用、Chromium 已安装、`data/` 与 `cookie/` 可写、有外网（前端 CDN）、准备一条已生成好的预览作为兜底。
